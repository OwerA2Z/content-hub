# 本地化图片素材库

## Goal

建设一个独立的本地化图片素材库，用于集中保存和复用通用封面、配图及其他图片素材。文章、每日候选池和微信公众号草稿都可以从素材库选择图片，避免重复填写外部图片 URL。

## Background

- 当前文章只保存可选的 `coverUrl` 和 `images` URL，没有独立素材实体。
- 微信公众号创建草稿需要封面图；个人主体发布受限时，管理员需要复制内容并手动操作，因此图片素材必须容易预览和复用。
- 项目使用 Docker Compose 和 PostgreSQL，首版明确采用本地文件持久化，不接入 OSS/S3/MinIO。

## Requirements

### 素材管理

- 首版只支持图片：JPG、PNG、WebP、GIF。
- 单张图片最大 10 MB。
- 支持上传、预览、搜索、标签、复制素材 URL、归档和删除。
- 保存原始文件到可配置的本地目录，默认使用 `./data/media`；Docker 部署必须通过持久化 volume 保存。
- PostgreSQL 保存素材元数据，不把二进制图片写入数据库。
- 每个素材有稳定 ID、原始文件名、存储路径、MIME 类型、大小、标签、状态和创建时间。

### 内容关联

- 文章详情可以从素材库选择一张封面图，并继续兼容已有 `coverUrl`。
- 文章正文图片可以关联素材库图片；首版不强制改写历史 HTML。
- 每日候选池支持指定封面素材，接受候选保存为文章时保留关联。
- 微信公众号草稿优先使用关联素材；没有素材时才使用兼容的公网 `coverUrl`/`images[0]`。
- 公众号草稿前置校验必须明确提示“缺少封面素材”，并提供跳转素材库的入口。

### 权限与接口

- 新增 Scope：`media:read`、`media:write`、`media:delete`。
- 管理员可以管理全部素材；外部调用方按 Scope 访问素材接口。
- 上传接口使用 `multipart/form-data`，返回素材元数据和可访问 URL。
- 列表接口支持关键词、标签、状态和分页。
- 删除采用软删除/归档，默认不影响已关联文章；物理文件清理由后续清理任务处理。

## Out of Scope

- 首版不支持视频、音频、文档和压缩包。
- 首版不接入第三方对象存储、CDN、图片编辑器和自动裁剪。
- 首版不自动从正文 HTML 中提取并上传所有远程图片。
- 首版不实现多人协作、素材版权识别和复杂使用统计。

## Acceptance Criteria

- [ ] 后台有独立“素材库”菜单，不与文章管理或 API 中心混合。
- [ ] 管理员可以上传图片并在页面看到缩略图、文件名、大小、标签和状态。
- [ ] 图片文件重启应用后仍可访问，Docker volume 配置完整。
- [ ] 文章详情可以选择素材作为封面，并保存关联。
- [ ] 候选池预览/接受流程可以保留候选封面素材。
- [ ] 没有封面素材时，创建微信公众号草稿会在前端和后端给出明确提示。
- [ ] AI/外部系统可使用 `media:read` 读取素材，使用 `media:write` 上传素材，不能仅凭文章写入权限管理素材。
- [ ] 已有关联素材的文章归档或删除素材后，文章记录不丢失且能显示素材失效状态。
- [ ] 通过类型检查、测试、构建、差异检查，并验证本地文件持久化路径。
